# 表格取值保真与预处理清理方案（代码级）

日期：2026-11-21　范围：Knowhere worker 的表格解析（Excel / CSV / TSV / Markdown 竖线表格 / PDF 页面表格）

## 1. 目标

1. 表格转成网页表格（HTML）后，每一格显示的内容和原文件一致：不出现 `NaN`、`1.0`、科学计数法，也不丢开头的 0、`+` 号或小数末尾的 0。
2. 解析不会因为文件本身合法、只是写法少见（单列 CSV、文件名带方括号）而整份失败。
3. 删掉重复和互相不一致的预处理，同一个单元格在不同环节转成的文字保持一致。

不改的地方：Word 表格（本来就按原文字取）、Markdown 里直接写的 HTML 表格（原样透传）、Excel 的区域切分、表头识别和 Luna 合并逻辑、检索侧的表格查询。

## 2. 实测问题清单

以下结果都是用当前代码跑出来的（脚本放在本地临时目录，没有提交）。

| # | 环节 | 输入 | 现在的结果 | 影响 |
|---|---|---|---|---|
| 1 | Markdown 竖线表格 | `\|N/A\|null\|`、空格子（不带空格的紧凑写法） | 全部显示成 `NaN` | 改值 |
| 2 | Markdown 竖线表格 | 两列同名 `x`、`x` | 第二列被改名为 `x .1` | 改表头 |
| 3 | Markdown 竖线表格 | 某格以 `"` 开头 | 后面几行被并进同一格 | 表格结构被破坏 |
| 4 | Markdown 竖线表格 | 数字列里有空格子 | 数字变成 `1.0` | 改值 |
| 5 | CSV | 只有一列 | 报 `CSV_DELIMITER_UNDETECTED`，整份解析失败 | 解析失败 |
| 6 | CSV | 只有一列，但内容里带逗号（如 `hello, world`） | 同上，整份解析失败 | 解析失败 |
| 7 | CSV | 文件名带 `[]:*?/\`（如 `report[2024].csv`） | 报 `INVALID_SHEET_TITLE`，整份解析失败 | 解析失败 |
| 8 | CSV | `001`、`1.10`、`+86138…`、`1e5` | 变成 `1`、`1.1`、`86138…`、`100000` | 改值 |
| 9 | CSV 编码 | GB18030 编码、字节数为偶数的小文件 | 抽样 2000 条短文本，有 261 条会被错当成 UTF-16 解码，出现乱码 | 乱码 |
| 10 | Excel | 只有日期的单元格 | 显示成 `2024-01-01 00:00:00` | 显示和 Excel 不一致 |
| 11 | Excel | 百分比 `15%`、布尔值 `TRUE` | 显示成 `0.15`、`True` | 显示和 Excel 不一致 |
| 12 | Excel | 带千分位或固定小数位格式的数字 | 显示成原始数值，格式被忽略 | 显示和 Excel 不一致 |
| 13 | PDF 页面表格 | 数字列里有空格子 | 读表时已被转成数字，结果是 `1.0`，开头的 0 丢失 | 改值 |

冗余或不一致的地方：

- **单元格转文字有 4 套写法：** 网页表格、表头识别、Luna 合并预览、附属区域文字各自把单元格转成文字，规则不一样。比如同一个 `2024.0`，网页上显示 `2024`，交给表头识别模型的却是 `2024.0`。
- **合并单元格查询函数重复：** `merge_at` 和 `_covering_merge` 是同一个函数写了两遍。
- **编码尝试顺序有冗余：** `utf-8-sig` 已经能处理不带 BOM 的 UTF-8，后面再试一次 `utf-8` 是多余的。没有 BOM 的 UTF-16 被放在 GB18030 前面，这正是第 9 条乱码的原因。
- **页数估算重复转换：** 估算页数时把 CSV/xls 完整转换一遍，解析时又转换一遍。xls 要调用 LibreOffice，等于转两次。见 4.6。

## 3. 统一原则

1. **数据原样进来、原样出去：** 只有确定不改变显示的转换才做。
2. **保留基本预处理：** 去掉格子两边的空白，统一换行。
3. **不加阈值或猜测类规则：**
   - CSV 的分隔符只在常见的几种里识别；
   - Markdown 表格按通用的 Markdown 表格规则切分；
   - Excel 按单元格自己设置的显示格式来显示。

## 4. 改动清单

### 4.1 Markdown 竖线表格：去掉 pandas

文件：`apps/worker/app/services/document_parser/tables/table_text_parser.py` 中的 `extract_tables_by_forms`（第 105–128 行）

- 新增 `_split_md_row(line) -> list[str]`：
  - 先去掉行首和行尾的 `|`，再按没有转义的 `|` 切分；
  - `\|` 还原成字符 `|`；
  - 每格去掉两边的空白。
- 分隔行沿用现在的判断：整行每一格都只含 `-`、`:` 和空白，就去掉这一行。
- 第一行作为表头，其余作为数据，在本文件内生成网页表格（`<thead>` 里用 `<th>`，`<tbody>` 里用 `<td>`，内容做 HTML 转义），结构和原来 pandas 的输出一致。
  - 没有复用检索侧的 `grid_to_html`：解析器不应该依赖检索模块。
- 删除这个函数里的 `pd.read_table` 和 `to_html`。`df2md` 仍在给目录解析用，不动。
- 上游列数对齐（`markdown/parser.py` 的 `clean_md_table_lines`）改成按切好的格子数对齐，原来是数竖线个数。
  - 好处一：`\|` 不再被当成多出来的一列。
  - 好处二：修掉了原来截断多余列时连行尾竖线一起删掉、导致最后一列丢失的问题。

### 4.2 CSV / TSV 读入

文件：`apps/worker/app/services/document_parser/formats/excel/normalize.py`

1. **编码**（`_TABLE_TEXT_ENCODINGS`、`_decode_table_text`）：
   - 带 UTF-16 的 BOM 时按 UTF-16 解码；
   - 其余按 `utf-8-sig` → `gb18030` → `latin-1` 依次尝试；
   - 删掉多余的 `utf-8`，以及不带 BOM 时的 `utf-16`。
2. **分隔符**（`_read_delimited_rows`）：
   - `csv.Sniffer().sniff(text, delimiters=",\t;|")`，只在这几种常见分隔符里识别；
   - 识别不出时，说明文件里没有统一的分隔符，按单列读取（以 `,` 作为分隔符，并按 CSV 规则处理引号），不再报错；
   - 删除 `CSV_DELIMITER_UNDETECTED` 这个失败分支。
3. **工作表名**（`_sheet_title_from_stem`）：
   - 把 Excel 不允许出现在表名里的 `[]:*?/\` 替换成 `_`；
   - 再按 Excel 规定的 31 字符上限截取。这个上限是文件格式本身的规定，现有代码就有，不是新加的。
4. **数字判定**（`_cell_value`、`_parse_int`、`_parse_float`）：
   - 先去掉两边的空白；
   - 只有当这个数字按 4.4 的统一规则显示出来与去空白后的原文完全一样时，才存成数字，否则保留原文；
   - 例子：`12`、`3.5`、` 12 ` 存成数字；`001`、`1.10`、`+86…`、`1e5`、`-0`、`1_000` 保留原文；
   - `=` 开头的字段仍按文字保存，和现在一样。

### 4.4 Excel 单元格统一转成文字

文件：`apps/worker/app/services/document_parser/formats/excel/workbook_grid.py`、`html_render.py`、`header_detect.py`、`luna_decisions.py`、`satellite_merge.py`

1. `GridCell` 新增 `number_format: str`，在 `_sheet_from_pair` 里从读取数值的那份工作簿取出。
2. 在 `workbook_grid.py` 新增唯一的 `cell_text(cell) -> str`，替换以下 4 处：
   - `html_render._display_text`（第 259 行）；
   - `header_detect._visual_cell_text`（第 347 行）里的转文字部分。它原有的空白折叠保留，那是为了让发给模型的提示更紧凑；
   - `luna_decisions._cell_preview`（第 438 行）；
   - `satellite_merge.format_region_cells`（第 326 行起）。
3. `cell_text` 的规则（D1 已定为方案 A）：
   - **先把格式代码清理成只剩代码本身（`_format_codes`）：**
     - 用一个切分规则（`_FORMAT_TOKEN_RE`）把格式切成：引号里的文字、`\年` 这类转义字符、`[Red]`/`[>100]`/`[$-804]` 这类方括号标记、`_)` 这类占位空白、`* ` 这类填充，以及单个格式字符；
     - 去掉前五类，剩下的统一转成小写。
     - 不用 openpyxl 的 `is_datetime`：它区分大小写，用真实文件实测时，`YYYY-MM-DD` 格式的日期被它当成时间，显示成了 `00:00`。
   - **日期和时间：**
     - 清理后的格式代码里有 `d` 或 `y` 就显示日期，有 `h` 或 `s` 就显示时间；
     - 统一输出 `YYYY-MM-DD`、`HH:MM` 或 `YYYY-MM-DD HH:MM`；
     - 格式里含秒时才带秒；
     - 时长值（openpyxl 只对 `[h]:mm` 这类格式给出时长）输出累计小时，例如 `27:05`。
   - **百分比：** 乘以 100 后加 `%`。
   - **固定小数位：**
     - `0` 表示必须显示的位数，`#` 表示可省的位数，例如 `0.0#` 把 2.5 显示成 `2.5`，把 2.567 显示成 `2.57`；
     - 用十进制四舍五入（遇到 5 进位，负数同理，`Decimal` 的 `ROUND_HALF_UP`）：
       - Python 自带的浮点格式化会把 `9.225` 显示成 `9.22`、把 `2.5` 显示成 `2`；
       - 百分比先在十进制下乘 100，例如 `0.0145` 显示为 `1.45%`，不会出现 `1.4499…`。
   - **按千缩放：** 最后一个数字占位符后面紧跟的逗号，每个表示除以 1000，例如 `0.0,,` 把 12345678 显示成 `12.3`。不做这一步，配上后面的单位 `"M"` 就会显示成错的 `12345678.0M`。
   - **数字后面的文字（单位）：**
     - 第一段格式里、最后一个数字占位符（`0`、`#`、`?` 或 General）之后的文字照原样接在数字后面，例如 `0.00"x"` 显示 `3.25x`，`#,##0.00"万元"` 显示 `1234.50万元`，`0 "kg"` 显示 `12 kg`；
     - 数字前面的文字不显示，所以 `"¥"#,##0.00`、`$#,##0` 这类货币前缀仍然不加；方括号里的货币标记也不显示；
     - `%`、`,`、`.` 是格式字符，不当成文字；末尾的空白去掉。
   - **布尔值：** 显示成 `TRUE` / `FALSE`。
   - **其余格式：** 包括"常规"、文本、科学计数、分数，以及千分位和货币符号，都沿用"常规"格式的显示规则（`general_number_text`）：整数形式的浮点数去掉 `.0`，其他用 `str`。
4. 删除重复的 `_covering_merge`：`merge_at` 和读取工作簿时共用同一个 `_merge_in`。
5. `GridCell` 新增必填字段 `number_format`。合并单元格中原本没有内容的格子，格式记为 `General`（openpyxl 的 `FORMAT_GENERAL`）。

### 4.5 不改

### 4.6 页数估算不再重复转换

`page_estimator.py`：

- CSV/TSV 改用 `_count_delimited`：用 `normalize.read_delimited_rows`（解析时读 CSV 用的同一个函数）读出各行，数不为空字符串的字段，不再写 xlsx。
  - 解析写 xlsx 时只有空字符串存成空格子，其余字段（包括只有空白的字段和 `=` 开头的字段）都成为有内容的格子，所以两种数法结果相同。
- xls 仍要先转成 xlsx 再数（`_count_xls`，就是原来的 `_count_spreadsheet`，只处理 xls）。
- 计费方法名 `xlsx_cells` / `xls_conversion` 不变。

计数结果必须和现在完全一致，因为它影响计费。

## 5. 决策

| # | 问题 | 结论 |
|---|---|---|
| D1 | Excel 按显示格式还原到什么程度 | 2026-11-21 定为方案 A：日期、时间、百分比、小数位、布尔值按格式显示，不加千分位和货币符号。原因：表格查询工具把网页表格当文字读入 SQLite，`1,234.50` 这种带千分位的写法没法直接当数字计算。同日补充：格式里写在数字后面的单位要显示出来（例如 `12万元`），计算时由 Agent 自行处理；不另加一列单位，因为那会改变表格结构，而且同一列各格的单位可能不同 |
| D2 | 4.6 页数估算 | 2026-11-21 决定一并处理：只改 CSV/TSV，xls 不动 |
| D3 | CSV 两边带空白的数字 | 保留基本预处理：判断是不是数字时不看两边的空白，例如 ` 12 ` 存成数字 12；不是数字的文字保持原样 |
