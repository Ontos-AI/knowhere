# Local MinerU Codex Export Validation Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Demonstrate that the standalone Knowhere local MinerU exporter is statically sound, regression-safe, functional with real local PDF and DOCX inputs, reproducible, and honest about offline and document-fidelity limitations.

**Architecture:** Validation is layered so failures can be localized: environment preflight, repository checks, isolated contract tests, database-backed regressions, static-fixture reproducibility, and real model-backed PDF/DOCX smoke tests. Real tests use only generated synthetic documents and write temporary review packages under the ignored `.codex-review/validation/` directory.

**Tech Stack:** Python 3.13, uv, pytest, Ruff, Pyright, MinerU pipeline backend, PostgreSQL 16, LibreOffice, PyMuPDF, PowerShell, SHA-256.

## Global Constraints

- Use only synthetic fixtures generated by repository scripts.
- Do not call the MinerU cloud API or start a MinerU HTTP server.
- Run the MinerU backend with `MINERU_MODEL_SOURCE=local`, `MINERU_DEVICE_MODE=cpu`, `HF_HUB_OFFLINE=1`, and `TRANSFORMERS_OFFLINE=1`.
- Treat `offline_verified` as false unless an external firewall or network namespace independently blocks traffic.
- Do not equate DOCX logical pages with LibreOffice normalized-PDF pages.
- Preserve table HTML; treat CSV as best-effort and verify fidelity metadata.
- Remove generated source documents, review packages, coverage data, and caches after evidence is recorded.
- Do not push, merge, or open a pull request.
